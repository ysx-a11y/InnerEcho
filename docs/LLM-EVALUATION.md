# LLM 解读质量评测

该评测用于提示词或模型变更前的本地质量检查，不属于普通单元测试，也不会在 CI 中调用真实接口。

## 数据边界

- `scripts/llm-eval.ts` 内的 6 个样本全部为合成情境，不得替换为线上卷宗或用户原话。
- 评测只读取当前进程的 `LLM_API_KEY`，不写入 `.env`、报告文件或测试快照。
- 默认不打印完整模型输出；临时人工复核可设置 `LLM_EVAL_VERBOSE=1`，输出仅出现在当前终端。
- 每次运行会把合成输入、实际提示词、完整输出、单次耗时、Token、拒绝判断和评分写入 `docs/evaluations/LLM-EVAL-LATEST.md`，不会记录密钥。

## 运行方式

PowerShell 示例：

```powershell
$env:LLM_API_KEY='<temporary-key>'
$env:LLM_EVAL_RUNS='2'
$env:LLM_EVAL_TOKEN_BUDGET='100000'
npm run eval:llm
Remove-Item Env:LLM_API_KEY
```

可配置项：

- `LLM_EVAL_RUNS`：每个样本运行次数，范围 1～3，默认 2。
- `LLM_EVAL_MAX_TOKENS`：单次最大输出，范围 300～2000，默认 1200。
- `LLM_EVAL_TOKEN_BUDGET`：整批硬预算，最大 2,000,000，默认 100,000。
- `LLM_EVAL_VERBOSE=1`：打印合成样本的完整模型输出和各项检查。
- `LLM_EVAL_REPORT`：自定义 Markdown 报告路径；必须位于当前工作区内。

## 当前自动检查

- 核心字段、称号长度、分数范围和关键词数量；
- 是否引用合成样本中的具体事实，而非只输出通用套话；
- 是否无依据诊断、绝对化、推断性别或引用交互遥测；
- 是否跨题库串词；
- 权力／控制主题是否保留边界、沟通和停止权；
- 是否使用温和、可选择的建议；
- 是否过度依赖灯塔、盔甲、港湾等高频模板意象；
- 同一输入重复生成时的文本相似度，仅作为稳定性观察，不作为越相似越好的指标。

自动分数不能替代人工阅读。上线前至少人工抽查最低分样本、涉及关系边界的样本，以及同一输入差异最大的两次结果。
