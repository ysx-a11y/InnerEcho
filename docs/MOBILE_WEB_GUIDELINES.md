# InnerEcho 移动端 Web 与渐进式加载规范

本规范用于约束 InnerEcho 的移动端 Web 界面、交互行为、资源加载和个人数据请求方式，是 [`DEVELOPMENT.md`](./DEVELOPMENT.md) 的补充规范。

文中的“必须”是合并门槛；“应当”允许在有明确依据时例外，例外需要在代码注释或 PR 描述中说明原因。

## 1. 核心原则

1. **移动端优先**：先保证 320px～430px 宽度下可用，再增强平板和桌面端布局。
2. **首屏只做首屏需要的事**：首屏关键 UI、样式和必要字体优先，其余资源按用户路径渐进加载。
3. **用户意图优先于后台任务**：点击、提交、切换页面等前台请求必须能暂停或让位于推测性预加载。
4. **公共资源可以预测，个人详情不可猜测**：可预加载公共静态资源和高概率下一步组件；不得预取用户未点击的个人档案、答案、报告详情或私密图片。
5. **列表只返回列表所需字段**：列表和概览接口不得夹带完整详情。用户点击某条记录后，才请求该条记录的详情。
6. **性能优化不能牺牲隐私和正确性**：不得把敏感数据放进静态 HTML、隐藏 DOM、Service Worker 公共缓存、URL 参数或可被第三方脚本读取的全局变量。

## 2. 移动端 Web 布局规范

### 2.1 视口与安全区域

页面必须保留正确的移动端视口配置：

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover" />
```

- 页面根容器使用 `min-height: 100dvh`；仅在需要兼容旧浏览器时增加 `100vh` 作为回退。
- 顶部、底部固定区域必须处理刘海屏和系统手势区：

```css
.page {
  min-height: 100vh;
  min-height: 100dvh;
  padding-top: env(safe-area-inset-top);
  padding-bottom: env(safe-area-inset-bottom);
}
```

- 不得用固定页面高度截断内容；内容区应允许自然增长和纵向滚动。
- 横向滚动只能用于明确的横向内容容器，不得用全局 `overflow-x: hidden` 掩盖布局溢出问题。

### 2.2 响应式布局

- 默认样式面向窄屏，桌面增强使用 `min-width` 媒体查询。
- 主内容在手机端应保持单列；需要多列时，必须验证 320px 宽度下无挤压、截断和误触。
- 容器宽度应使用流式尺寸，并设置合理上限：

```css
.content {
  width: min(100% - 1.5rem, 52rem);
  margin-inline: auto;
}
```

- Flex/Grid 子项包含长文本时必须设置 `min-width: 0`。
- 文本、邮箱、ID、链接和用户输入必须可换行；禁止依赖固定字数维持布局。
- 图片和视频默认 `max-width: 100%; height: auto;`，明确尺寸或 `aspect-ratio`，避免加载后布局跳动。

### 2.3 触控与输入

- 可点击区域最小为 `44px × 44px`，相邻高频操作应保留至少 8px 间距。
- 不能只依赖 `hover` 暴露功能；触屏用户必须能通过点击、聚焦或常驻按钮完成相同行为。
- 使用语义化 `button`、`a`、`input`，不得用仅绑定 `onClick` 的 `div` 代替按钮。
- 表单输入必须有可关联的 `label`，并根据内容设置正确的 `type`、`inputMode` 和 `autocomplete`。
- 提交按钮在请求期间应防止重复提交，但必须保留清晰的加载状态；失败后允许重试且不得清空用户已输入内容。
- 打开软键盘后，当前输入框和主要操作按钮应保持可见；不得用固定底栏遮挡输入区。

### 2.4 导航、弹层与返回行为

- 底部导航必须避开 `safe-area-inset-bottom`，并为正文预留相同高度，避免覆盖内容。
- Modal/Drawer 打开时锁定背景滚动；关闭后恢复原滚动位置。
- 弹层必须支持明确的关闭按钮、键盘 `Escape` 和合理的焦点管理。
- 浏览器返回键应优先关闭当前临时弹层或返回上一步，不得直接丢失未提交表单。
- 页面切换后应根据场景恢复列表滚动位置；进入全新流程时再滚动到顶部。

### 2.5 可访问性与设备偏好

- 正文和交互文字必须满足可读的颜色对比度，不能仅靠颜色表达状态。
- 图标按钮必须提供 `aria-label`；装饰图标应从辅助技术中隐藏。
- 动画应遵循 `prefers-reduced-motion`；减少动画时不得影响功能完成。
- 加载状态优先使用稳定骨架屏或局部占位，避免全屏闪烁和布局跳动。
- 所有关键流程必须至少验证触屏、键盘和屏幕旋转后的可用性。

## 3. 页面渲染策略

### 3.1 首屏必须渲染

以下内容属于首屏关键内容，应随当前页面立即渲染：

- 应用外壳、当前页面标题、主导航和首个主要操作；
- 当前页面完成基本交互所需的 CSS 和最小 JavaScript；
- 首屏可见的轻量占位、错误边界和加载状态；
- 首屏可见且不可替代的品牌资源，例如一个必要字体字重或首屏主视觉。

首屏不得等待统计数据、历史记录、非当前 Tab、海报导出、编辑器、图表详情等次要能力才显示。

### 3.2 可以预渲染

预渲染指提前创建**不包含个人详情**且结果确定的轻量 UI，以减少用户感知等待。可以预渲染：

- 应用外壳、导航、静态标题、卡片框架；
- 下一步页面的骨架屏和通用空状态；
- 当前列表可见区域的摘要卡片；
- 纯本地、无副作用、体积小的派生视图。

不得为了“秒开”把以下内容放进隐藏 DOM：

- 用户报告全文、问卷答案、私密描述和未展示的个人图片；
- 大型图表、海报、Canvas 或完整的离屏页面；
- 需要请求个人详情接口才能生成的内容。

非首屏长内容可以使用 `content-visibility: auto` 降低渲染成本，但必须提供合理的占位尺寸：

```css
.belowFoldSection {
  content-visibility: auto;
  contain-intrinsic-size: auto 420px;
}
```

### 3.3 懒渲染与懒加载

- 非当前路由或 Tab 的大型 React 组件必须使用动态导入。
- 图表、海报导出、富文本编辑器等重型功能应在进入相关页面或产生明确意图后加载。
- 首屏以下图片使用 `loading="lazy"`；首屏关键图片不得懒加载，并应设置 `fetchpriority="high"`。
- 长列表必须分页或游标加载；数据量增长后应使用虚拟列表，禁止一次渲染全部历史记录。
- 进入视口才需要的数据使用 `IntersectionObserver`，不得用高频 `scroll` 监听器反复计算。

## 4. 资源加载分级

| 级别 | 资源类型 | 策略 | 示例 |
| --- | --- | --- | --- |
| P0 必需 | 当前首屏 CSS、应用入口、必要字体、首屏关键图 | 立即加载；谨慎 `preload` | 当前页面样式、首屏 Logo |
| P1 高概率下一步 | 下一步路由组件、内置题库、通用交互模块 | 页面稳定后按优先级预加载 | 登录弹层、题库选择页、下一步问卷引擎 |
| P2 明确意图 | 用户指向或即将点击的公共资源 | `pointerdown`、`focus`、受支持设备上的 `pointerenter` 时提升优先级 | 某张题库、某个编辑器组件 |
| P3 点击后加载 | 个人详情、低概率重型模块、导出能力 | 点击后请求；显示局部骨架 | 单份卷宗详情、报告全文、海报导出模块 |
| 禁止预取 | 敏感详情、无上限集合、用户未选择的大图 | 不预加载、不预渲染、不进入公共缓存 | 全部历史详情、全部私密照片、完整答案集 |

### 4.1 预加载规则

- `preload` 只用于当前导航中确定会用到的关键资源。每增加一项都必须说明它对首屏渲染的直接价值。
- `modulepreload`/动态 `import()` 用于高概率下一步代码；不得在启动时预加载所有路由。
- 预加载任务必须去重、限制并发，并能被用户发起的请求让位。
- 推测性任务应在首屏可交互后，通过 `requestIdleCallback` 或有上限的回退定时器调度。
- `navigator.connection.saveData === true` 时必须关闭推测性预加载。
- 慢网下应减少预取数量和资源体积；不得因预加载阻塞当前页面请求。
- 预加载失败不得阻断当前页面；用户真正点击时仍需正常重试。
- 对内置题库等有限公共集合可以设置明确上限；不得预取数量不受控的用户自建内容。

项目已有 `src/utils/progressiveLoading.ts` 和 `src/utils/journeyPreloads.ts`，新增渐进式加载应优先复用这套协调器，不另建互不感知的后台队列。

### 4.2 字体、图片和媒体

- 字体只加载实际使用的字重和字符集；关键字体优先 WOFF2，并配置 `font-display: swap`。
- 不得预加载所有字体。首屏只预加载会立即使用且对品牌表达必要的字体文件。
- 图片必须提供与显示尺寸匹配的压缩版本；响应式图片使用 `srcset`/`sizes`。
- 列表缩略图与详情原图必须使用不同资源，列表不得下载原图后再用 CSS 缩小。
- 非关键图片应懒加载和异步解码：`loading="lazy" decoding="async"`。
- 视频和音频默认不预载完整文件；列表场景使用 `preload="none"`，需要元信息时才用 `metadata`。

### 4.3 缓存策略

- 带内容哈希的公共静态资源：`Cache-Control: public, max-age=31536000, immutable`。
- HTML 和入口清单：短缓存或协商缓存，确保新版本能及时生效。
- 登录用户的概览/列表响应：按业务选择 `private` 短缓存或 `no-store`，不得进入共享缓存。
- 私密详情、完整答案、报告全文和敏感图片：默认 `Cache-Control: private, no-store`。
- Service Worker 不得缓存鉴权接口、个人详情响应或带身份信息的请求，除非已有经过评审的加密离线方案。
- 退出登录、切换账号和注销账号时，必须清除内存中的个人详情状态和与账号绑定的客户端缓存。

## 5. 个人数据按需加载规范

### 5.1 数据分层

个人数据必须拆成三个层级，接口和类型也应分别定义：

1. **概览（Overview）**：昵称、头像缩略图、报告数量、最后活动时间等当前页面立即展示的信息。
2. **列表摘要（Summary）**：记录 ID、标题、创建时间、状态、缩略图等绘制一行列表所需的最小字段。
3. **详情（Detail）**：完整问卷、答案、分析结果、私密描述、原图等只在详情页展示的数据。

列表摘要类型不得包含详情对象：

```ts
interface DossierSummary {
  id: string;
  title: string;
  createdAt: string;
  status: 'pending' | 'ready' | 'failed';
  thumbnailUrl?: string;
}

interface DossierDetail extends DossierSummary {
  diagnosticResult: DiagnosticResult;
  answers: Record<string, unknown>;
}
```

### 5.2 API 边界

建议采用独立端点，避免通过查询参数让同一个列表接口偶尔返回全部详情：

```text
GET /api/auth/stats
GET /api/auth/dossiers?cursor=<cursor>&limit=20
GET /api/auth/dossiers/:id
```

- 列表接口必须分页，只查询和返回摘要字段，不得先从数据库解密/解析完整详情再在路由层删除字段。
- 详情接口必须同时校验登录状态和记录所有权；仅知道 ID 不代表有权读取。
- 详情 ID 必须通过 `encodeURIComponent` 构造 URL，服务端继续做格式校验。
- 不得把答案、报告正文或隐私字段放在 URL、埋点、日志和错误消息中。
- 接口响应使用明确类型并在边界校验，不使用 `any` 传递个人数据。

### 5.3 客户端行为

- 打开个人中心时只请求概览和第一页摘要。
- 用户点击某条摘要后才请求该记录详情；请求期间显示对应详情区域骨架，不阻塞整个个人中心。
- 快速切换记录或离开页面时，使用 `AbortController` 取消已失效请求，并避免旧响应覆盖新选择。
- 同一次登录会话中，可以在内存里按 ID 短暂复用已打开详情；退出登录后必须清空。
- 默认不把敏感详情持久化到 `localStorage`、`sessionStorage`、IndexedDB 或 URL state。
- 详情加载失败应保留摘要和返回路径，并提供局部重试按钮。
- 用户点击的详情请求优先级高于所有后台预加载任务。

示例：

```ts
useEffect(() => {
  if (!selectedId) return;

  const controller = new AbortController();
  setDetailState({ status: 'loading' });

  apiGet<DossierDetail>(
    `/api/auth/dossiers/${encodeURIComponent(selectedId)}`,
    { signal: controller.signal },
  )
    .then(({ data }) => setDetailState({ status: 'ready', data }))
    .catch((error) => {
      if (error.name !== 'AbortError') setDetailState({ status: 'error' });
    });

  return () => controller.abort();
}, [selectedId]);
```

> 示例表达的是生命周期和数据边界。实际调用参数应以项目 `apiGet` 的类型定义为准，不得通过类型断言绕过不兼容。

## 6. React/Vite 实现约束

- 页面级和重型功能使用 `React.lazy` + 动态 `import()` 拆包，`Suspense` fallback 应与目标区域尺寸接近。
- 不得在组件渲染期间发请求或启动预加载；副作用放入 Hook、事件处理器或项目加载协调器。
- `useEffect` 中的请求必须处理卸载、取消、失败和竞态。
- 同一资源不得同时由 `<link rel="preload">`、动态导入和自定义 fetch 重复下载。
- 不得为了减少请求数把所有页面重新打进一个入口包；以真实用户路径和构建产物为依据调整拆包。
- 开发阶段应检查 Vite 构建输出，避免首包意外包含图表、海报导出、管理端和全部题库。
- 组件应保持稳定的加载、空数据、失败和成功四类状态，不得把“尚未请求”错误展示成“没有数据”。

## 7. 性能预算与观测

以下目标以中端手机、移动网络和生产构建为准：

- LCP：应低于 2.5 秒；
- INP：应低于 200 毫秒；
- CLS：应低于 0.1；
- 首屏关键资源不得被低优先级预取挤占；
- 新增超过 50KB gzip 的前端依赖或单个懒加载块时，必须说明必要性和加载时机。

性能数据应区分页面、设备等级和网络类型。埋点只记录耗时、状态码、资源类型等非敏感元数据，不得记录个人答案、报告正文、令牌或完整请求体。

## 8. 验收清单

### 移动端界面

- [ ] 320px、375px、390px、430px 宽度下无页面级横向溢出。
- [ ] iOS Safari 和 Android Chrome 下安全区域、`100dvh`、软键盘行为正常。
- [ ] 触控目标不小于 44px，关键功能不依赖 hover。
- [ ] 长文本、超长邮箱和用户输入不会撑破卡片。
- [ ] 加载前后无明显布局跳动，减少动画设置有效。

### 资源加载

- [ ] 首屏只加载当前页面必需资源。
- [ ] 预加载有明确优先级、数量上限和去重机制。
- [ ] 开启省流量模式后不执行推测性预加载。
- [ ] 首屏图片有尺寸；非首屏图片懒加载；列表使用缩略图而非原图。
- [ ] 用户点击产生的请求不会被后台预加载阻塞。

### 个人数据

- [ ] 个人中心首开只请求概览和分页摘要。
- [ ] 列表响应不包含完整答案、报告全文、私密描述或原图。
- [ ] 只有点击具体记录后才请求该记录详情。
- [ ] 详情接口验证当前用户对记录的所有权。
- [ ] 切换记录会取消过期请求，退出登录会清空个人详情缓存。
- [ ] 敏感详情不进入公共缓存、持久化存储、URL、埋点或日志。

## 9. 当前项目落地提示

- `src/utils/progressiveLoading.ts` 已提供省流量判断、优先级、去重、暂停和空闲调度，应作为公共资源预加载的统一入口。
- `src/utils/journeyPreloads.ts` 已按用户流程预加载登录、题库选择、基础信息和问卷资源；新增任务时必须继续保持有限集合和明确上限。
- `src/components/PersonalView.tsx` 当前通过 `/api/auth/dossiers` 获取历史数据。后续实现本规范时，应把该接口调整为分页摘要，并增加受所有权校验保护的 `GET /api/auth/dossiers/:id`，点击记录后再加载详情。
