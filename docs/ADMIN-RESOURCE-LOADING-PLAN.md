# 管理端资源加载与按需预加载计划

> 状态：规划文档，尚未实施  
> 更新日期：2026-08-20  
> 范围：`admin.html`、`src/admin/` 及管理端列表/详情接口

## 1. 为什么与用户端分开

管理端和用户端应继续保持独立入口、独立构建和独立加载策略。

| 维度 | 用户端 | 管理端 |
| --- | --- | --- |
| 核心目标 | 首屏快、弱网可用、关键旅程顺滑 | 登录页轻、非当前工作台按需加载、重数据不阻塞 |
| 使用频率 | 公开访问，流量较高 | 少量管理员，低频访问 |
| 典型路径 | 首页 → 登录/基础信息 → 题库 → 答题 → 结果 | 登录 → 概览 → 某个工作台 → 列表 → 详情 |
| 可预取内容 | 已知下一步的静态代码与公开题库 | 鉴权后的静态页面代码；不得提前拉取敏感业务数据 |
| 缓存重点 | 静态资源与二次访问体验 | 哈希静态资源；HTML 和业务数据保持新鲜 |

当前项目已经用 `vite.config.admin.ts` 将管理端输出到 `dist-admin/`，没有把用户端 SPA、文章页、站点地图或用户端 Service Worker 带入管理端。这一边界应当保留。

## 2. 当前状态

### 2.1 构建产物基线

2026-08-20 的生产构建中，管理端初始资源约为：

- React vendor：`110.83 KB gzip`
- 图标 vendor：`12.34 KB gzip`
- 管理端应用代码：`86.22 KB gzip`
- runtime：`0.36 KB gzip`
- 管理端 CSS：`7.96 KB gzip`
- 初始 JavaScript 合计：约 `209.75 KB gzip`

### 2.2 前端加载问题

`src/admin/AdminApp.tsx` 静态导入了全部九个工作台。管理员即使只打开登录页或概览，也会下载卷宗、用户、题库、回响、行为分析、提示词、任务和安全审计页面的代码。

`src/admin/components/TelemetryStats.tsx` 还静态导入了三套完整内置题库。它们同时在用户端题库注册表中按需导入，因此构建器会报告动态导入失效。行为分析实际只需要题目 ID、标题和题库名称，不需要完整题库定义。

### 2.3 数据加载问题

- 卷宗列表使用 `SELECT *`，随后执行完整卷宗解密与格式化；列表响应包含头像、遥测、答案和较长诊断字段，而项目已经有独立详情接口。
- 任务列表会解密并返回完整文本及附件数组；附件可能包含较大的 Data URL，不适合随列表分页返回。
- 页面代码和接口数据目前没有清晰的“列表摘要 → 点击后详情”边界。

这些数据问题比单纯减少几 KB 前端代码更值得优先处理，因为它们同时消耗数据库、解密 CPU、网络和浏览器内存。

## 3. 目标策略

### 3.1 首次打开管理端

初始入口只保留：

- `AdminLogin`
- 鉴权状态恢复所需代码
- 登录成功后的基础外壳、导航、Toast 和错误边界
- React 与当前页面实际使用的图标

九个工作台使用 `React.lazy` 独立分块。未登录时不得下载工作台代码，也不得请求任何管理业务数据。

### 3.2 登录成功后

1. 鉴权成功后立即加载默认的 `Dashboard`。
2. 浏览器空闲时只预取一个高概率工作台，不并行拉取全部标签页。
3. 导航项发生 `pointerenter`、`focus` 或 `pointerdown` 时，提高对应页面代码的加载优先级。
4. 点击导航后显示稳定的局部骨架屏，不让整个管理外壳闪烁或消失。
5. 页面模块加载完成并挂载后，才请求该页面的数据。

默认不预加载卷宗详情、任务附件、用户详情等敏感数据。代码预取与数据预取必须是两套独立机制。

### 3.3 建议的优先级

| 触发时机 | 加载内容 | 优先级 |
| --- | --- | --- |
| 未登录 | 登录页、鉴权恢复 | 最高 |
| 鉴权成功 | 概览页面代码与概览数据 | 最高 |
| 用户指向导航项 | 对应工作台代码 | 高 |
| 浏览器空闲 | 至多一个高频工作台代码 | 低 |
| 点击列表项 | 对应详情数据和详情组件 | 即时 |
| 未发生用户意图 | 详情数据、附件、全量题库 | 禁止预取 |

管理端使用人数较少，不需要建立复杂的全页面预测系统。简单、可取消、由用户意图驱动的加载策略更合适。

## 4. 分阶段实施

### P0：标签页代码分块

- 将九个工作台改为 `React.lazy` 动态导入。
- 保留 `AdminLogin` 和管理外壳为同步依赖。
- 为内容区增加统一 `Suspense` 骨架屏。
- 导航项支持 hover、键盘 focus 和触屏 pointerdown 预取对应模块。
- 确保同一模块的预取与实际渲染复用同一个 Promise，避免重复请求。

验收标准：

- `admin.html` 的初始依赖不再包含全部工作台代码。
- 打开登录页时，网络面板中没有非必要工作台 chunk。
- 切换每个标签页时只新增对应 chunk，重复访问不重复下载。
- 初始 JavaScript 目标不高于 `160 KB gzip`；如 React vendor 无法进一步拆减，应重点考核管理端自有初始代码不高于 `35 KB gzip`。

### P1：行为分析移除完整题库依赖

- 建立轻量题库元数据/题目标题索引，或由后端遥测接口返回展示所需名称。
- `TelemetryStats` 不再静态导入三套完整题库定义。
- 消除三条 `INEFFECTIVE_DYNAMIC_IMPORT` 构建警告。

验收标准：

- 行为分析 chunk 不包含完整题库的选项、评分和长描述。
- 用户端题库仍保持独立动态 chunk。
- 行为分析中的题库名和题目标题展示不退化。

### P1：卷宗列表摘要化

- 列表 SQL 只查询筛选、排序和列表展示需要的列。
- 列表 DTO 不返回完整诊断、答题载荷、遥测、长文本或媒体附件。
- 点击卷宗后继续通过现有详情接口按 ID 获取完整内容。
- 保留服务端分页、筛选和排序，不在浏览器拉全量后处理。

验收标准：

- 单页卷宗列表响应不含答案、遥测、完整诊断和媒体内容。
- 列表阶段不执行无关字段的解密/JSON 解析。
- 详情弹窗的信息保持完整。
- 为列表 DTO 与详情 DTO 分别增加接口测试，防止重字段回流。

### P1：任务列表摘要化

- 列表只返回任务标识、用户摘要、标题、分类、状态和时间。
- 文本正文只在展开详情时获取。
- 附件元数据与附件内容分离；列表不得携带 Base64/Data URL。
- 若暂无任务详情接口，新增按任务记录 ID 获取详情的受保护端点。

验收标准：

- 任务列表响应不含完整正文和附件内容。
- 打开详情时才产生解密与附件传输。
- 大附件不会扩大列表分页响应或阻塞首屏。

### P2：缓存、取消与可观测性

- 哈希 JS/CSS 使用长期 immutable 缓存，`admin.html` 保持 `no-cache`。
- 管理 API、鉴权响应和敏感详情不得进入 Service Worker 或公开缓存。
- 快速切换筛选、日期和标签页时，用 `AbortController` 取消旧请求。
- 记录各工作台 chunk 加载时间、接口耗时、响应体大小和错误率。
- 只缓存当前会话内可安全复用的轻量字典数据，并在退出登录时清空。

## 5. 不做的事情

- 不在登录前预取管理业务接口。
- 不在登录后一次性预取全部九个工作台。
- 不用 Service Worker 缓存管理 API 响应、卷宗详情或附件。
- 不把管理端页面并回用户端入口或共享用户端的旅程预加载队列。
- 不为了减少请求数重新合并为单一巨型 bundle。

## 6. 回归检查清单

- 无令牌、失效令牌和退出登录后不能残留或展示管理数据。
- 登录、刷新恢复、退出和再次登录流程正常。
- 九个导航标签均可通过鼠标、键盘和触屏进入。
- 快速连续切换标签时，旧请求不会覆盖新页面状态。
- 卷宗与任务列表分页、筛选、排序和详情展示一致。
- `npm run typecheck`、`npm test`、`npm run build` 全部通过。
- 构建报告记录初始资源和各标签页 chunk 的 gzip 大小，与本文件基线对比。

## 7. 推荐执行顺序

建议按照以下顺序落地：

1. 标签页代码分块与统一骨架屏。
2. 行为分析改用轻量题目索引。
3. 卷宗列表摘要/详情分离。
4. 任务列表摘要/详情分离。
5. 请求取消、指标采集和预算门禁。

前两项改动集中在前端，风险较低；卷宗和任务摘要化涉及 API 合约，应分别提交并配套测试，便于审查和回滚。
